# B1 story rewrite

The complete B1 v2 catalog contains 200 rewritten stories, each 619–769 German words, within the requested 600–800 range. Every edition includes reviewed English sentence translations, contextual word meanings, two source-supported comprehension questions and one continuous Qwen character recording. All 200 final recordings passed source/voice hashes, waveform, duration, whole-story transcript coverage and spoken-word alignment checks. These checks do not replace independent teacher review or listening to every recording.

`content/reading/b1-rewrite-drafts.json` retains the resumable accepted-source checkpoint. Its `automatedReview.pass` field only records a model check; it is **not** editorial acceptance. Generated drafts have shown chronology errors, repeated material and awkward German even when that field is true. Review every story against its original plot, fix the German, and set `reviewStatus` to `editorially-accepted` only after that review. The source hash and `node scripts/audit-b1-drafts.mjs --rewrite` detect stale drafts and mechanical failures.

ChatGPT-reviewed revisions live as individual `content/reading/b1-reviews/reading-b1-NN-v2.txt` files. After checking a revision's plot, chronology and German, run `node scripts/import-b1-reviews.mjs --only=reading-b1-NN-v1`. This validates the 600–800-word range and stores the accepted text in the source checkpoint. A later change to an accepted file requires `--replace` and another review. This review is not independent teacher review.

The current rewrite is authored and reviewed directly in the ChatGPT session, as requested. The optional `node --env-file=.env.local scripts/generate-b1-rewrites.mjs --max-new=10` provider script remains available for a future authorized run. It uses the existing Groq credential, writes atomically after each story and stops on a provider quota error. Its output still requires editorial review. Never put the credential in this file or the repository.

For release, use new `-v2` story IDs so old `-v1` completion records remain intact, and redirect old story URLs. Generate sentence translations and glosses against the accepted text. Then create exact dialogue plans and Qwen narration for the new IDs, validate text hashes, alignment and coverage, and inspect representative audio. The audio generator supports `--level B1` and `--bitrate-kbps 16`; compare audible quality and the expanded Sites package size before selecting the final bitrate. Run the full test suite and build before publishing. Do not deploy a partial replacement.

`node scripts/prepare-b1-reviewed-audio.mjs --out-dir=.local-piper/b1-reviewed-audio` creates exact `sources.json` and `plans.json` from accepted review files and manually checked quote assignments in `speakers.json`. The Qwen generator accepts those files with `--source-json` and `--dialogue-plan`; pass `--output-dir content/reading/b1-reviews/audio` and `--manifest-path content/reading/b1-reviews/audio-manifest.json` to keep recordings staged outside the live site. Use `--checkpoint .local-piper/b1-reviewed-audio/checkpoints` so validated WAV chunks survive temporary-directory cleanup and remain available for re-encoding. The repository test checks every staged recording against its reviewed text and timing sidecar. Staged audio is not referenced by the app until the full release.

The restored local runtime is `.local-piper/qwen-venv/bin/python`, with narration, ASR and alignment models in `.local-piper/qwen-models`. These ignored development files are excluded from deployment. Earlier `/tmp/leselaut-qwen-*` paths were cleared by the operating system; check availability before reusing them. The Desktop checkout can also contain cloud placeholders marked `dataless`. Use a clean validation copy at the same Git commit when those reads stall, preserving local edits and verifying recovered source files against their Git blob hashes.

## Support and English review

All 200 accepted German editions contain 600–800 words. Their original metadata and text are retained in `content/reading/b1-reviews/original-editions.json` so source hashes and legacy progress remain recoverable after the catalog switches to v2.

`node scripts/prepare-b1-reading-support.mjs` prepares source-matched vocabulary examples, reuse links and per-story hover meanings. The reviewed dictionary contains 3,081 additional forms. All 824 vocabulary examples are exact sentences from the new editions; 173 missing old forms were replaced contextually. Reuse links must contain the linked word in both the new story and the earlier source. Tests check complete hover coverage and catch previously misleading automatic lemma suggestions.

The local Marian German–English model produces sentence and paragraph drafts without provider calls. These drafts are not publication-ready. `sentence-translation-edits.reviewed.json` records ChatGPT's contextual corrections by exact German sentence. `translation-reviews.json` records the German source hash and sentence count only after every sentence in that story has been compared. `node scripts/prepare-b1-sentence-translations.mjs` builds staged output; its `--require-complete` mode rejects publication until all 200 reviews match the current text. A changed source invalidates its review.

All 200 English editions have been reviewed, with 2,972 contextual corrections. The final narration manifest contains 200 recordings matching the accepted text and voice plans. Earlier checkpoints with 114 recordings and 89 tests were preparation milestones; the final release replaces the entire B1 collection together.

All 400 comprehension answers were compared against the rewritten plots. `question-reviews.json` binds each reviewed question to the German source hash and supporting sentences. Story 16’s explanation now refers to the actual applause; story 170 explicitly describes removing a photo from the selection before publication. The 91-test source-review checkpoint preceded complete narration and release activation.

## Complete-release preparation

`node scripts/prepare-b1-release.mjs` audits the complete German, English, vocabulary, questions and dialogue plans without changing the app. Use `--audio-root=/absolute/generation/checkout` to audit the active generation checkout's manifest and files. `--apply` rejects the release before writing anything unless all 200 recordings match the final text and voice hashes, WebM headers and strictly increasing spoken-word timings. Once ready, it switches both B1 catalogs, sentence translations, narration plans and manifests together, updates coverage IDs, and retires only the previous generated B1 media. The archived v1 source and user progress are preserved.

`app/lib/reading-editions.json` now selects B1 edition 2. Story bookmarks and legacy course/reception links resolve through the current edition. Future edition IDs remain unavailable. Progress merging retains v1 results, while v2 requires its own completion. The release tests also prove that an incomplete audio batch cannot change the published catalog.

The production build and all 96 tests passed with Node 22.19.0 after full release activation and vocabulary integration. The expanded build occupies 211.23 MiB, below the 256 MiB hosting limit. The 200 new B1 recordings and timing sidecars occupy 115.15 MiB; the previous 23.49 MiB of generated B1 media was retired after every replacement validated. Measure the final expanded Sites archive against the 256 MiB limit. Models, WAV checkpoints and staged source media remain outside the deployment archive.

The final vocabulary integration normalizes 22 contextual forms to dictionary headwords and adds 19 missing standalone cards. Three words reuse existing cards. The catalog now contains 4,142 cards (871 A1, 1,100 A2 and 2,171 B1); every previous card ID remains intact. Inflected forms such as `ausblieb` and `zugestimmt` remain in their actual source examples while their review cards use `ausbleiben` and `zustimmen`.

The generator now accepts optional `--batch-size 2` for uncached chunks using the same reference voice. A local two-clip benchmark reduced per-clip generation time by approximately 1.59× and passed transcript coverage checks for both clips. Every generated chunk still receives the existing waveform, duration, ASR and alignment validation; unsuccessful batch chunks fall back to the original sequential retries. Already validated recordings and chunks are reused. Keep the release validation checkout in `.local-piper/b1-release-checkout` to preserve it across temporary-directory cleanup. The practical reading component retains its client boundary while linking to the current story edition.
